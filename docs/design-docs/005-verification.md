## Figmaとの照合

参照対応は[visual-manifest.json](../design/visual-manifest.json)、素材のノードとSHA-256は[asset-manifest.json](../design/asset-manifest.json)。取得時のFigma PNGは`output/figma/reference-*.png`、ブラウザ画像は`output/playwright/`、比較用コンタクトシートは`compare-*.jpg`と`feedback-compare-*.jpg`に保存した。

初回比較で修正した項目は、Mobileの白いメモと折り返し、公開カードの216px基準、縦配置の進行ボタン、履歴のQマーカー付き選択、回答者の2列選択、シート高さ、待機表示、結果カードの実名・匿名記号、PCドラッグの白枠・挿入線、補助UIのボタン幅・種類。固定文言は既存Figmaと採用済み提案から取った。

次の差は画像全体のpixel-perfect合格として扱っていない。

- ユーザー指定によるTablerの図形、線端、線幅。Figma固有の紙とQのしっぽは書き直さずexportを保存。
- FigmaとChromiumのフォント描画・アンチエイリアス。字体はNoto Sans JP / Nunito、指定サイズ・太さ・行高を使用。
- シートの参照では背景画面が省略されているが、実装は起動元画面を半透明背景の下へ保持する。シート本体を比較する。
- 参照に含まれる人数・選択・スクロール・ドラッグ位置はその瞬間の例。実際のデータと操作で変わる。PCの閲覧者公開例は6カード、固定fixtureは10回答を保持する。PC閲覧者の予想画面はFigmaの選択タブと表示リストに不整合があるため、表示中の履歴種別に選択タブを合わせる。

これは初回の目視比較であり、固定baselineへの自動pixel-diffによる全画面合格ではない。実装を「完全一致確認済み」とはしない。Figmaが変更された場合は参照画像を再取得して確認する。

## 実装上の判断

1つのSPAで衝突しないクラス名を使うため、当初のCSS Modules案から共通styles.cssへ簡略化した。状態は外部ストアのRoomViewをuseSyncExternalStoreで購読し、画面へpropsで渡す。別の状態管理ライブラリは追加していない。

結果が不明なコマンドは再接続後も同じUUIDで再送する。履歴読み込みの再試行は、その読み込みだけをやり直す。初回認証後に入室が失敗しても再試行できるよう、token取得とroom入室を分けた。再プレイ後には同じroomの旧セッションのブラウザ下書きを削除する。

長文では回答カードと名前の行を内容に合わせて伸ばし、既存の一覧内でスクロールする。Figmaの通常データの最小寸法を保ち、回答本文を省略しない。お題のタッチ並べ替えはdnd-kit 0.5.0の既定値（250ms・5px）を使用する。

DockerのNode 24ベースはmulti-architecture digestを固定した。Linux arm64で起動を検証済み。amd64は同じDockerfileで構築可能な対象だが、今回の実行結果ではない。

本番JSは約614kB、gzip約188kBで、Viteの500kB警告が残る。機能は動作するが、遅い回線での初回表示時間はDiscord実機試験で計測する。警告を隠すための閾値変更はしていない。

## まだ実施していない受入

- 実際のApplication認証、Discord Desktop / Web / iOS / Androidのiframe、URL Mapping経由のWSSとフォント読み込み。
- 実機IME、画面回転、PIP / grid、バックグラウンド・画面ロック、セーフエリアとソフトウェアキーボード。
- 自宅Linux / nginx / 公開DNS / 証明書 / 接続継続時間、実回線の復帰時間。
- 50お題蓄積時の負荷、常時メトリクス、バックアップの定期実行と別媒体転送。
- 電源断・ディスク枯渇の実機試験。テストのDB書込み失敗と再起動はそれらの代替とはしない。

実装とローカル検証を終えた段階で、公開済み・Discord全端末の受入済みという意味ではない。次の実機受入は[IMPLEMENTATION_PLAN](../IMPLEMENTATION_PLAN.md)のチェック項目に沿って行う。
